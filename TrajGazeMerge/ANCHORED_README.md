# TrajGazeMerge + Anchor variant

This branch adds an **anchored** variant of TrajGazeMerge on top of the
existing TrajGazeMerge no-KD recipe, plus the infrastructure to train and
evaluate it on a combined 3-way dataset (StreamGaze_v2 + EgoGazeVQA + HD-EPIC,
val = held-out egtea recordings + held-out HD-EPIC participant P09).

## What the anchored variant does

In the standard TrajGazeMerge, the top-10% spatial patches by encoder score
become receivers and the bottom 90% are softly merged into them.

In the **anchored** variant, every spatial patch that contains a **gaze**,
**left-hand**, or **right-hand** position in any trajectory frame is **forced
into the receiver set first**; the encoder's score then fills the remaining
slots in the 10% budget. Net token budget unchanged.

Implementation: a large constant `ANCHOR_BOOST = 1e6` is added to
`scores_all` at anchor positions before `gaze_weighted_merge`'s argsort.
With a uniform boost, argsort naturally puts all anchors first; the top-(N-r)
cut keeps the highest-score anchors when `|anchors| > budget` (Default A).

Code:
- `TrajGazeMerge/models/merge.py` :: `compute_anchor_mask_for_qwen`
- `TrajGazeMerge/training/train_merge_lora_no_kd_anchored.py`

## Result headline (4,936-item combined val, per-source)

| Method                        | Tokens | SG egtea | EG egtea | HD-EPIC P09 | Combined |
|-------------------------------|--------|----------|----------|-------------|----------|
| Baseline LoRA                 | 100%   | 70.34    | 51.34    | 37.71       | **42.52** |
| TrajGazeMerge no-KD           | 10%    | 64.45    | 53.81    | 35.85       | 41.00    |
| VisionZip + LoRA              | 10%    | 72.43    | 52.99    | 36.46       | 41.92    |
| **TrajGazeMerge + Anchor**    | **10%**| 60.08    | 54.64    | **37.91**   | **41.92** (epoch_01.pth) |

The anchored variant ties VisionZip on combined at 10× compression while
keeping the merge-vs-full gap consistently positive (merge ≥ full at every
epoch on combined; merge > full at every epoch on HD-EPIC).

## Best-checkpoint caveat

The in-script `evaluate()` truncates val to the first 500 items, which all
fall within StreamGaze egtea (526 items first in the combined order). On
the full 4,936-item combined val, the anchored variant peaks at
**epoch_01.pth (41.92%)** — *not* at the saved `best.pth` (which was selected
by the SG-only subset). Deployed models should use `epoch_01.pth` rather
than `best.pth`, or re-train with full-val-based model selection.

```
/workspace/HD-EPIC/                                 (hd-epic.github.io)
  video/{P##}/{stem}.mp4
  Hands-Masks/contours_preds/{stem}.json            dense predicted hand masks
  SLAM-and-Gaze/{P##}/GAZE_HAND/mps_*.zip           (gaze unused; see note)
  frames_extracted/{P##}/{stem}/frame_{N:06d}.jpg   ← see tools/extract_hdepic_frames.sh
  hand_locations/{stem}.json                        ← tools/parse_hdepic_hands.py
  interaction/{stem}.npz                            ← tools/make_hdepic_interaction.py
  val_items.json                                    ← auto-saved on first val construction

/workspace/hd-epic-annotations/vqa-benchmark/*.json (cloned from hd-epic/hd-epic-annotations)
```

Note: HD-EPIC eye-gaze is in Aria MPS (radians, CPF frame); projecting to
image pixels requires the `projectaria_tools` SDK and is **out of scope for
this branch**. The pipeline treats HD-EPIC gaze as absent; the
`compute_traj_features` algorithm gracefully degrades (gaze-dependent terms
zero out, hand-driven signal still flows). The anchor mechanism then anchors
only on hand cells for HD-EPIC items — which is precisely where the variant
shows its largest win over the unanchored baseline (HD-EPIC merge > full at
every epoch).

## Setup

```bash
# 1. Clone this branch
git clone https://github.com/Jaewoo97/trajgaze.git
cd trajgaze && git checkout trajgazemerge-anchored

# 2. Env (Python 3.10, CUDA 12.1, torch 2.4.1)
#    minimum: transformers >= 4.51.3, peft >= 0.14, pycocotools, matplotlib

# 3. Pre-extract HD-EPIC frames (10 fps, 224×224 -- ~12 GB)
bash tools/extract_hdepic_frames.sh    # see contents — parallel ffmpeg over /workspace/HD-EPIC/video

# 4. Parse HD-EPIC hand mask centroids -> per-frame JSON
python tools/parse_hdepic_hands.py --workers 24

# 5. Build interaction.npz for EgoGazeVQA and HD-EPIC
python tools/make_egogaze_interaction.py
python tools/make_hdepic_interaction.py
```

## Train

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 torchrun --nproc_per_node=4 --master_port=29710 \
  -m TrajGazeMerge.training.train_merge_lora_no_kd_anchored \
  --stage1-ckpt path/to/TrajGaze_v2/checkpoints/stage1_v3/best.pth \
  --output-dir path/to/output/merge_lora_no_kd_anchored \
  --epochs 3 --lr-lora 1e-4 --lr-enc 1e-5 --merge-ratio 0.9 \
  --grad-accum 4 --log-every 10 --eval-every 600
```

## Evaluate (per-source over all 4,936 combined val items)

```bash
python -m TrajGazeMerge.eval.eval_full_1011 \
  --stage anchored_merge \
  --ckpt path/to/merge_lora_no_kd_anchored/epoch_01.pth \
  --gpu 0 --merge-ratio 0.9
```

The eval script also supports `--stage {baseline,merge,visionzip,random_merge}`
for direct comparison rows.

## Visualize selected tokens

```bash
python -m TrajGazeMerge.viz.viz_selected_tokens \
  --ckpt path/to/merge_lora_no_kd_anchored/epoch_01.pth \
  --out  path/to/viz_outputs/anchored \
  --split test --n-per-source 4 --sources sg eg hd --gpu 0
```

For each item, renders 4 sampled frames with the encoder's 14×14 importance
heatmap overlaid and the top-10% (or anchored-then-top-up) patches outlined
in lime green.

## VisionZip dependency

`train_visionzip_lora.py` requires the patched Qwen2.5-VL from
[`dvlab-research/VisionZip`](https://github.com/dvlab-research/VisionZip)
placed at `/workspace/EgoGazeVQA/VisionZip/Qwen2_5_VL/qwen2_5vl_visionzip.py`.
This branch additionally requires two patches to that file:

1. The upstream-documented rotary-dtype fix (`apply_rotary_pos_emb_flashatt`
   should `q.float()` and `k.float()` before `apply_rotary_emb`).
2. A chunked-scoring rewrite to avoid OOM on long video sequences — replace
   the `if return_logits:` block in `Qwen2_5_VLVisionFlashAttention2.forward`
   with a per-head, query-chunked softmax-column-sum producing `[H, 1, T]`
   instead of materializing the `[H, T, T]` map. The encoder's
   `mean(0).sum(0)` reduction is mathematically identical to the original.
