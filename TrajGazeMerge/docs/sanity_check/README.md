# sanity_check — viz vs no-overlay, per dataset

Generated by `scripts/make_sanity_check_figures.py`. One figure per dataset: the overlay
variant on top, the marker-free variant below, sampled at four points across one clip.

**What they are checking.** The two trees must be *index-aligned* — frame `k` of the
no-overlay tree must be the same moment as frame `k` of the overlay tree, differing only by
the gaze marker. Both loaders address frames by index, so a tree that holds the right
**number** of frames but samples different moments desynchronises student and teacher,
raises no error, and shrinks nothing visible. It is only detectable in pixels.

**Why EG reads ~0.4 and SG ~3.0.** EG's `gaze`/`no_gaze` are two renders of the *same*
encode, so only the marker pixels differ and the JPEG noise is identical. SG's `viz` and
`original` are separate encodes of the same footage, so noise differs everywhere. Both are
correct; the scales are simply not comparable across the two benchmarks.

## `SG-egoexolearn_REPAIR.png` — what a failure looks like

Three rows: `viz`, the repaired tree, and the tree as it was before. The bottom row shows
entirely different scenes at the same index (MAD 29.7 / 29.5 / 62.5 / 46.2) while the middle
row matches `viz` with only the marker gone (MAD 2.6–2.8).

54 of 180 egoexolearn stems were in that state, and **every one of them had exactly the
right frame count**. See `kd_handoff_v2.md` §7.4a for the root cause (`-r` as an ffmpeg
*input* option re-spaces VFR frames; `setpts=N/RATE/TB` is index-based and does not).

## Reading a figure

- **MAD 0.3–5** — same moment, marker removed. Correct.
- **MAD 6–12** — usually still correct on fast-moving clips; confirm the value is minimised
  at zero frame offset, which is what the verifier's V-shape test does.
- **MAD 15+, flat across offsets** — different footage. Do not train on it.
